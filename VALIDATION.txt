BOUNDARIES
- The large production SWLOR_Haks submodule was not downloaded here.
  Submodule safety was exercised with disposable local Git fixtures.
- The actual Toolset GUI, NWN asset discovery, area generation, full clean
  installation via the launcher buttons, and successful/early-exit application
  startup were not exercised in this session. The user's screenshot and
  supplied earlier validation are separate evidence, not tests run here.
- Network interruption/retry and concurrent external edits were not simulated.
  Verified complete archives are reused; partial downloads restart.
- Main source is never reset, cleaned or automatically updated. Version 1.1
  explicitly fetches and fast-forwards on Update and launch, and moves HAK
  only to the pin in that update. Changed files/history cause refusal.
  Install initializes only a missing, empty, official pinned HAK submodule.
  Existing initialized HAK revisions must match the main HEAD gitlink and
  contain no tracked or untracked edits. Rebuild does not initialize HAKs.
- Real GitHub-to-HAK updating and the complete GUI update/build/launch flow
  were not exercised end to end; update tests used disposable local Git
  fixtures. A missing or rewritten shallow ancestor causes safe refusal.
- Launch requires an existing build and the private SDK receipt from setup;
  it performs no download or build. It still validates Module and configures
  Module Root, preserving other settings and backing up any changed JSON.
- Tools and NuGet packages are fetched on first setup, not bundled in the ZIP.
  Future upstream changes or network restrictions may affect installation.
- The EXE is unsigned. No commercial signing certificate was used.
